## O README responde às perguntas principais

Um README eficaz permite perceber rapidamente o que é o projeto, para quem serve, como começar, como verificar o resultado e onde encontrar informação adicional.

## Estrutura-base

1. **Nome e resumo:** uma ou duas frases sobre o propósito.
2. **Estado:** indicar se é experimental, em desenvolvimento ou estável, com data quando relevante.
3. **Funcionalidades:** o que o projeto faz e o que não faz.
4. **Pré-requisitos:** versões, ferramentas e permissões necessárias.
5. **Instalação:** passos ordenados e comandos reproduzíveis.
6. **Utilização:** exemplo mínimo de entrada e resultado esperado.
7. **Testes:** comandos executados e resultados reais; não declarar testes que não foram executados.
8. **Estrutura:** pastas principais e respetiva função.
9. **Limitações e segurança:** riscos conhecidos, dados tratados e segredos que nunca devem ser publicados.
10. **Contribuição:** como propor alterações e reportar problemas.
11. **Licença e contactos:** apenas quando definidos e apropriados.

Nem todo projeto precisa de todas as secções. Prefira remover uma secção irrelevante a mantê-la vazia.

## Estrutura de pastas

Organize por função e não por uma divisão excessivamente profunda. Use nomes consistentes, evite duplicar o mesmo documento em várias pastas e crie índices quando o número de ficheiros justificar.

Um README de pasta deve explicar:
- finalidade da pasta;
- lista ou mapa dos documentos;
- sequência de leitura ou execução;
- dependências e critérios de conclusão;
- limitações e ligações para referências oficiais.

## Atualização responsável

Quando o comportamento, comandos, versões ou estrutura mudarem, atualize o README na mesma alteração ou abra uma Issue para acompanhar a atualização. Datas e badges não substituem evidência. Uma imagem deve ter texto alternativo; uma ligação deve ter um destino válido.

## Exercício verificável

Escolha um projeto de treino e avalie o seu README usando a checklist. Reescreva o resumo e a secção “Como começar”. Peça a outra pessoa para seguir as instruções sem explicação oral e registe onde teve dúvidas.

## Checklist

- [ ] O propósito é claro nos primeiros parágrafos.
- [ ] Os pré-requisitos são explícitos.
- [ ] Os passos estão ordenados e são reproduzíveis.
- [ ] Os resultados descritos foram observados.
- [ ] Limitações e riscos estão identificados.
- [ ] Ligações e caminhos foram verificados.
- [ ] Não há segredos, credenciais ou dados privados.
