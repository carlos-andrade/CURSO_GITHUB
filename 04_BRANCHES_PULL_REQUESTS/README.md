## Fluxo recomendado

Branch de trabalho → alteração pequena → revisão do diff → push → Pull Request → checks → revisão → correções → merge autorizado → confirmação na branch de destino.

## Critérios de conclusão

- [ ] Criar uma branch a partir da base correta.
- [ ] Publicar uma alteração isolada.
- [ ] Abrir um PR com objetivo, teste e limitações.
- [ ] Rever o diff e interpretar checks.
- [ ] Resolver um conflito num repositório de treino.
- [ ] Registar evidências no relatório de exercício.

## Limites de segurança

Não contornar proteções, não integrar alterações sem checks obrigatórios e não usar comandos destrutivos para “limpar” um estado desconhecido.
