## Percurso recomendado

O curso começa pela interface web e só depois introduz o terminal. Não é necessário dominar programação para iniciar.

| Etapa | Trabalho | Resultado verificável |
|---|---|---|
| A | Orientação e preparação | Repositório de treino acessível e registo de progresso iniciado |
| B | Fundamentos e interface | README criado, editado e localizado no histórico |
| C | Git local | Alteração local enviada para um repositório remoto |
| D | Branches e Pull Requests | Alteração proposta, revista e integrada |
| E | Planeamento e documentação | Issue com objetivo, critérios e evidência |
| F | Actions e segurança | Verificação automática executada e segredos protegidos |
| G | Publicação e projeto final | Projeto utilizável, documentado e validado |

## Sessão de estudo sugerida

Para cada sessão de 30–60 minutos:

1. **5 min — recordar:** rever a última evidência e a próxima tarefa.
2. **10–15 min — compreender:** ler uma lição e consultar a fonte oficial.
3. **15–30 min — executar:** fazer a prática no repositório de treino.
4. **5–10 min — verificar:** comparar resultado observado com o esperado.
5. **5 min — registar:** atualizar o progresso e anotar dúvidas.

A duração é uma referência, não um critério de aprovação.

## Regra de progressão

Uma lição só passa a **validada** quando:
- os passos foram executados;
- o resultado foi observado no GitHub ou no terminal;
- os critérios de aceitação foram cumpridos;
- existe uma evidência que não expõe informação sensível;
- o aluno consegue explicar o que fez e como desfazer ou corrigir o erro mais provável.

Se algum ponto falhar, o estado fica **executado — por validar**. Não avançar por mera leitura.

## Trilhos de aprendizagem

- **Sem terminal:** começar pelos módulos 00, 01 e 02. O terminal passa a ser necessário no módulo 03.
- **Com terminal:** seguir a ordem completa; não saltar as verificações de segurança.
- **Aprendizagem aplicada:** usar um projeto próprio apenas quando não contiver dados confidenciais. Para experiências destrutivas, usar sempre o repositório de treino.

## Definição de concluído

O curso não se considera concluído por ter todas as páginas escritas. Exige a entrega do projeto final, evidências, checklist aprovada e registo de lições aprendidas.
