## A. Objetivo e documentação

- [ ] O README explica objetivo, público, âmbito e utilização.
- [ ] Os pré-requisitos e passos de execução estão explícitos, quando aplicáveis.
- [ ] A estrutura do repositório está explicada e é coerente.
- [ ] As ligações relevantes foram verificadas.
- [ ] Limitações e licença, quando aplicável, estão documentadas.

## B. Git e colaboração

- [ ] O histórico contém commits descritivos.
- [ ] Foi criada uma branch para uma alteração delimitada.
- [ ] A alteração foi proposta por Pull Request, salvo justificação documentada.
- [ ] O diff final foi revisto antes da integração.
- [ ] A Issue ou descrição do PR contém critérios de aceitação.
- [ ] Comentários de revisão relevantes foram resolvidos ou justificados.

## C. Validação e automatização

- [ ] As verificações relevantes para o projeto estão identificadas.
- [ ] O workflow ou teste foi executado e o link da execução está registado.
- [ ] Falhas foram investigadas e a correção foi confirmada por nova execução.
- [ ] O relatório distingue testes executados de testes planeados.
- [ ] Se não existir automatização, a decisão e a verificação alternativa estão justificadas.

## D. Segurança e governação

- [ ] Não há tokens, palavras-passe, chaves privadas ou segredos nos ficheiros.
- [ ] As permissões concedidas são proporcionais ao risco.
- [ ] As regras de branch e checks obrigatórios foram considerados.
- [ ] Dependências e conteúdo externo foram revistos conforme o âmbito.
- [ ] Dados pessoais e conteúdos de terceiros são tratados de forma adequada.

## E. Entrega

- [ ] A release ou publicação foi verificada, quando aplicável.
- [ ] A tag/release aponta para a versão esperada, se utilizada.
- [ ] O URL publicado foi aberto e testado, se aplicável.
- [ ] O relatório final contém ligações para as principais evidências.
- [ ] Limitações, riscos residuais e próximos passos estão registados.

## Evidência obrigatória

Para cada secção, indicar a evidência concreta: caminho do ficheiro, URL da Issue/PR/release, ligação da execução, resultado de teste ou justificação. Não basta escrever “feito” ou assinalar uma caixa sem suporte.

## Regra de aprovação

O projeto é aprovado quando todos os critérios aplicáveis estão cumpridos e demonstrados. Um critério não aplicável exige justificação. Um critério sem evidência permanece pendente; não pode ser considerado aprovado por inferência.
