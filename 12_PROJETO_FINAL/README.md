## Objetivo

Construir um repositório que outra pessoa consiga compreender, utilizar e manter. O projeto deve demonstrar documentação, histórico Git, colaboração, validação automática e governação proporcional ao risco. O tema é escolhido pelo aluno; não é necessário criar uma aplicação complexa para demonstrar boas práticas de GitHub.

## Entregáveis obrigatórios

1. **Repositório:** objetivo claro, estrutura coerente e ficheiros pertinentes.
2. **README:** propósito, pré-requisitos, instalação ou utilização, exemplos, limitações e licença quando aplicável.
3. **Planeamento:** pelo menos uma Issue com contexto, resultado esperado e critérios de aceitação.
4. **Fluxo Git:** branch de trabalho, commits descritivos, Pull Request e revisão do diff.
5. **Validação:** workflow ou verificação adequada ao tipo de projeto, com evidência de execução.
6. **Segurança:** ausência de segredos versionados e permissões proporcionais ao risco.
7. **Entrega:** release ou publicação, quando fizer sentido para o projeto.
8. **Relatório:** critérios cumpridos, ligações de evidência, limitações e trabalho pendente.

## Fases recomendadas

- **Fase A — Definir:** tema, público, objetivo, âmbito e critérios.
- **Fase B — Estruturar:** repositório, README inicial, pastas e Issue.
- **Fase C — Desenvolver:** branch, alterações pequenas e commits claros.
- **Fase D — Rever:** Pull Request, diff, comentários e verificações.
- **Fase E — Entregar:** merge conforme as regras do projeto; release/publicação quando aplicável.
- **Fase F — Auditar:** checklist, ligações, segurança, relatório e limitações.

Não avance de fase apenas porque o ficheiro foi criado. Registe evidência observável para cada critério.

## Regras de execução

- Use um repositório de treino ou um projeto próprio autorizado.
- Não publique credenciais, dados pessoais ou material sem autorização.
- Não marque um teste como executado sem o ter executado.
- Se uma funcionalidade não se aplicar, justifique a decisão no relatório.
- Se não tiver permissões para um passo, apresente uma alternativa verificável e registe a limitação.
- Corrija os problemas encontrados antes de declarar o projeto concluído.
